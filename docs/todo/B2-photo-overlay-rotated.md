## 증상
- 학습지를 옆으로 놓고 찍은 사진(예: 3-2 정육면체 숫자 문제)을 "사진 전체 읽기"하면, 인식은 맞게 된다(비전 프롬프트가 글자가 서는 방향으로 돌려 읽음)
- 그런데 **전개도 그리기 칸 밑과 3D 책 페이지에 깔리는 사진은 옆으로 누운 그대로**이고, 인식한 전개도(바로 선 방향)와 크기·위치도 맞지 않는다. 사진 위에서 전개도를 고치거나 비교할 수 없다
- 사용자 제보 화면(2026-10-31) 아래쪽: 칸 위 사진은 옆으로 누워 있고 면은 엉뚱한 자리

## 재현
1. 옆으로 누운 학습지 사진을 올리고 "사진 전체 읽기" (`VISION_ENGINE=agy` 또는 API)
2. 만들기 카드 ② 전개도 그리기 → 사진 맞추기 칸을 본다

## 원인
- "사진 전체 읽기"는 위치 정보가 없어 사진을 기본 자리(`NO_FIT`)에 둔다: `ui/App.tsx` `onPhoto` → `setFit(NO_FIT)`, `onScene`은 `place`(네모)가 있을 때만 `fitToBox` (`App.tsx` 360줄 근처)
- 인식 결과(ShapeScene)는 사진이 몇 도 돌아가 있었는지 돌려주지 않는다. 그래서 frontend는 사진을 돌릴 근거가 없다
- "이 부분 읽기"(네모)도 네모가 옆으로 누운 사진 기준이라, 바로 선 전개도와 가로세로가 바뀐다

## 진행
- 2026-10-31: 방법 1(사진 돌리기 ↺·↻) 구현 ([worksheets.md](../specs/worksheets.md) W5). 돌린 뒤 읽으면 칸 밑 사진과 전개도의 **방향**은 같다. "사진 전체 읽기"의 **위치·크기** 맞춤은 아직 `NO_FIT` → W8(`photoBox`)에서 끝낸다
- 2026-10-31: W8 구현. ↺로 세운 3-2를 전체 읽기하면 칸 밑·책 페이지 사진이 전개도와 정확히 겹친다. **이 버그는 끝** (P2 계약 합의 뒤 닫는다)

## 고치는 방향 (제안)
1. **사진 돌리기 버튼** (추천, 계약 변경 없음): 네모 단계에 "돌리기 ↻ 90°". 돌린 사진이 기준 사진이 된다(`PhotoUpload`의 `setBase`, 종이 펴기와 같은 길). [worksheets.md](../specs/worksheets.md) W5
2. (나중) 인식 결과에 사진 회전 각도를 같이 받기: ShapeScene 밖 응답 필드라 [api.md](../specs/api.md)부터 합의
- 어느 쪽이든 "사진 맞추기"의 방향 슬라이더로 지금도 손으로 맞출 수는 있다 (임시 방법)
