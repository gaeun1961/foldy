# three.js 뷰어 규칙

3D 뷰어(`frontend/src/viewer/`)의 좌표, 면 트리, 접기, 곡면 말기, 선, 꼭짓점 복사본·하이라이트, 클릭 규칙입니다. 데이터 형식은 [shape-scene.md](shape-scene.md)를 따릅니다.

## 공통

- **좌표**: three.js는 y가 위다. 도형 중심이 원점이고 x = 가로, y = 높이, z = 깊이(앞면이 +z 쪽, 보는 사람 쪽)다. [shape-scene.md](shape-scene.md)의 꼭짓점 규칙과 같은 위치다
- **펼침 값 `s`**: 모든 도형에서 0 = 입체(접힘·말림), 1 = 전개도(펼침)
- **`ViewerProps`**: UI는 이것만 넘긴다 (`frontend/src/viewer/index.ts`)
  - `scene: ShapeScene`: 그릴 도형. 바뀌면 다시 만든다. 단 `lines`만 바뀌면 선분만, 학습지 전개도 면 표시(grid 면 `text`·`fill`)만 바뀌면 면 표시만 다시 그린다 (선을 긋거나 면 표시를 쓸 때마다 카메라가 처음 구도로 돌아가지 않게)
  - `unfold?: number`: 펼침 값 `s` (0~1, 기본 0). 바뀌면 다시 만들지 않고 회전만 바꾼다. 슬라이더·애니메이션은 UI가 이 값을 바꿔서 만든다 (챗봇 화면 조작 TODO-10도 이 값을 쓴다)
  - `foldMode?: 'all' | 'step'`: 접는 방식 (기본 `'all'`). `'all'`은 모든 면이 `s`만큼 함께 접히고, `'step'`은 `s`를 전체 진행률로 보고 면을 하나씩 접는다 (아래 "단계별 접기"). 바뀌어도 다시 만들지 않는다
  - `showHiddenEdges?: boolean`: 가려진 모서리와 면 위 선분을 점선으로 보일지 (기본 `true`, 아래 "가려진 모서리", "선분"). 보기 옵션 체크박스 값이다. 바뀌어도 다시 만들지 않는다. 다른 보기 옵션도 이렇게 불리언 props 하나씩으로 더한다
  - `showMatchingEdges?: boolean`: 접으면 맞닿는 모서리 쌍을 같은 색으로 칠할지 (기본 `true`, 아래 "맞닿는 모서리"). 보기 옵션 체크박스 값이다. 바뀌어도 다시 만들지 않는다
  - `showVertexLabels?: boolean`: 꼭짓점 라벨(`vertexLabels`)을 보일지 (기본 `true`, 아래 "꼭짓점 복사본"). 보기 옵션 체크박스 값이다. 바뀌어도 다시 만들지 않는다
  - `highlightVertices?: number[]`: 강조할 꼭짓점 인덱스 목록 (기본 없음). 들어 있는 꼭짓점의 복사본을 모두 색으로 크게, 나머지 꼭짓점은 흐리게 보인다. 챗봇 화면 조작(TODO-10)이 쓴다. 비어 있지 않으면 화면에서 누른 꼭짓점보다 먼저다. 바뀌어도 다시 만들지 않는다
  - `pageResult?: { formula, value?, table?, general?, reveal?, lines? }`: 공식 결과. `lines`는 글자별 색으로 쓰는 설명 줄들(`{ text, link? }`, `link`는 그 줄 옆 작은 링크, 누르면 `onPageMenu(link.id)`). `value`가 없으면 식만, `table`은 (이름, 값) 열의 표, `general`은 일반 공식(글자별 색), `ratios`는 같은 크기로 강조하는 줄들(`{ label, value, note }`, 닮음비), `reveal`은 지금까지 나타난 줄 수(일반 공식 → 숫자 식 → 답, UI가 정한다)
  - `lesson?: { kind, progress, scale?, pi?, layers? } | null`: 설명 모드 (아래 "설명 모드"). `layers`는 원뿔 부피 마지막 단계의 원판 수. `cut`은 자르는 높이 h ÷ r(구 단면 비교, 회전체 단면). `cutKind`는 회전체 단면의 방향. `scale`은 닮음비 k(닮음만, 기본 2)이고, 바뀌면 설명 물체를 새로 만든다. `pi`는 원이 들어간 값의 표기(`'pi'` 기본, `'3.14'` 초등)이고, 곡면 도형에서 바뀌면 설명 물체를 새로 만든다. `kind`는 설명 종류(`'volume'` 부피, `'surface-area'` 겉넓이, `'diagonal'` 입체 대각선, `'shortest-path'` 겉면 최단 거리, `'edge-relations'` 모서리 위치 관계, `'similar'` 닮음, `'counts'` 면·모서리·꼭짓점 개수), `progress`는 0(시작 전)~1(끝). 없으면 보통 보기. `kind`가 바뀌면 설명 물체만 새로 만들고, `progress`만 바뀌면 값만 적용한다 (도형은 다시 만들지 않는다)
  - `drawLines?: boolean`: 선 긋기 모드 (기본 `false`, 아래 "선 긋기"). 켜져 있으면 클릭은 꼭짓점 강조·모서리 쌍 고르기 대신 선분의 끝점을 고른다
  - `edgeDivisions?: 2 | 3 | 4`: 선 긋기에서 모서리를 몇 등분할지 (기본 2 = 중점)
  - `onSceneChange?: (scene: ShapeScene) => void`: 선 긋기로 선분이 더해지면 새 ShapeScene(일반 데이터)을 넘긴다. UI가 이 값을 다시 `scene`으로 넘겨야 화면에 남는다
  - `onDrawState?: (state: 'idle' | 'picked' | 'no-path') => void`: 선 긋기 진행 상태. `idle` 첫 점을 기다림, `picked` 첫 점을 고름, `no-path` 겉면으로 이을 길을 찾지 못해 긋지 않음(드묾). UI가 안내 문구로 쓴다
  - `pageResult?: { formula: string; value: string }`: 공식 결과. 왼쪽 페이지에서 한 줄 설명 자리에 식과 큰 값을 찍는다. `pageText`나 `pageResult`만 바뀌면 책 그림만 다시 그린다(카메라·설명 진행은 그대로)
  - `pageMenu?: { id; label; active; enabled }[]`, `onPageMenu?: (id: string) => void`: 왼쪽 페이지 메뉴. 글 아래에 한 줄씩 그리고, 누르면(도형에 가려지지 않았을 때) `onPageMenu(id)`. 무엇을 할지는 UI가 정한다. 메뉴가 바뀌면 책 그림만 다시 그린다
  - `pageText?: string[]`: 책 장면 왼쪽 페이지에 찍을 글 (아래 "책 장면"). 첫 줄은 제목, 나머지는 본문 줄. 문구는 UI가 정한다(도형 이름·치수 등). 바뀌면 다시 만든다
  - `pageNumbers?: [number, number]`: 책 아래 귀퉁이에 찍을 왼쪽·오른쪽 쪽 번호 (기본 없음 = 찍지 않음). UI가 차례에 맞춰 정한다(ui.md "빈 책"). 바뀌면 다시 만든다
  - `photo?: { src: string; x: number; y: number; size: number; angle: number }`: 전개도를 따라 그린 학습지 사진 (TODO-36, 아래 "책 장면"). 전개도 그리기 칸에서 맞춘 위치 그대로, 단위는 칸(= 전개도 grid 좌표, 3D 길이 1). `x`, `y`는 사진 가운데, `size`는 사진이 비율대로 들어가는 정사각형의 한 변, `angle`은 칸에서 보이는 대로 시계 방향 각도(도). `net.layout`이 `grid`일 때만 그린다. 바뀌면 다시 만든다
  - `onRouteChoices?: (routes: Line<PolyhedronPoint>[][]) => void`: 선을 더할 때 길 후보 목록(첫째가 실제로 더한 길, 아래 "선 긋기"). 다른 면의 두 점이면 겉면 길을 짧은 순으로 전부, 접었을 때 같은 면 위 두 점이면 그 면 위 직선이 첫째이고 다른 면들을 지나는 길이 뒤를 잇는다(펼친 전개도에서 여러 면을 가로질러 보이는 선이 이런 경우가 있다). 후보가 하나면 UI는 버튼을 보이지 않는다. UI가 "다른 길" 버튼으로 방금 그은 선을 다른 후보로 바꾼다
  - `onFacePick?: (pick: { face: number; text: string | null; opposite: { face: number; text: string | null }[] } | null) => void`: 마주 보는 면 보기. 선 긋기가 아닐 때 면(꼭짓점·모서리 쌍이 아닌 곳)을 누르면 그 면과, 다 접었을 때 마주 보는 면(바깥 법선이 정반대인 면)을 같은 연보라로 칠하고 넘긴다. `text`는 학습지 전개도(grid) 면에 쓰인 글자(없으면 `null`). 바른 직육면체·정육면체는 `opposite`가 하나, 잘못된 전개도는 없거나 여럿일 수 있다. 같은 면을 다시 누르거나, 꼭짓점·모서리 쌍·빈 곳을 누르거나, 선 긋기를 켜면 풀리고 `null`. 전개도 상태에서도 칠해져서 펼친 채로 어느 면끼리 마주 보는지 보인다. 다 접으면 마주 보는 면이 바닥·뒤쪽에 가려지므로, 고른 두 면 위에 깊이 검사를 끈 반투명 연보라 판을 하나 더 그려 가려져도 비쳐 보이게 한다. UI가 안내 문구로 쓴다
  - `faceMarking?: boolean`, `onFaceMark?: (netFace: number) => void`: 면 표시 모드 (기본 `false`). 켜져 있으면 면을 눌러도 마주 보는 면 보기를 하지 않고, 학습지 전개도(grid)일 때 누른 면의 `scene.net.faces` 인덱스를 `onFaceMark`로 넘긴다. UI가 그 칸의 `text`·`fill`을 바꿔 다시 `scene`으로 넘긴다
- **`foldStepCount(scene)`**: 단계별 접기의 단계 수(접는 면 수). 면 트리가 없는 도형은 0. UI가 단계 버튼·단계 표시를 만들 때 쓴다 (`index.ts`에서 export)
- **설명 모드** (공식 시각화, [ui.md](ui.md) 친절한 설명 원칙): 입체 상태(`unfold = 0`)에서 도형 안팎에 설명 물체를 그려 공식이 왜 그런지 보여준다. 전개도(grid)로 접은 입체는 가운데가 원점이 아니고 가로·세로·높이 방향도 달라질 수 있어서, 치수(`boxSizeOf`)와 가운데(`boxCenterOf`)를 실제 꼭짓점에서 구하고 부피·대각선·닮음 물체를 그 자리로 옮긴다. 닫히지 않는 잘못된 전개도에서는 설명을 보여주지 않는다. **책 크기**: 입체로 보는 설명(`LESSON_POSE`가 `solid`)을 켜면 책을 그 범위(입체, 닮음은 큰 도형까지)에 맞춰 다시 만들고, 끄면 전개도 범위로 돌아간다. 전개도 크기의 책에서는 접은 도형이 작아 보이고 닮음의 큰 도형이 책 밖으로 나가서다. **모서리 길이 표시**: 계산하는 설명에는 길이 글자(예: `4 cm`)를 도형 위에 띄운다. 입체로 보는 부피·겉넓이·대각선은 앞 아래(가로)·오른쪽 아래(세로)·앞 왼쪽(높이) 모서리 바깥에, 전개도로 보는 최단 거리는 면마다 이웃한 두 변 안쪽에 붙여 접힘을 따라간다. 대각선은 계산해서 나온 밑면 대각선·입체 대각선 길이도 그 선이 다 그려진 뒤 선 위에 띄운다. 계산이 필요 없는 위치 관계·닮음에는 길이를 보이지 않는다. **겉넓이는 접힌 입체로 본다**: 칠한 면이 뒤쪽·아래쪽에서도 보이게 면을 반투명으로 칠한다. 묶음마다 대표 면(카메라에서 가장 잘 보이는 면) 하나로 과정을 보인다: ① 그 면을 칠한다 ② 재는 선(직사각형 가로·세로, 삼각형 밑변·높이, 그 밖 한 변)이 자라며 길이가 나온다 ③ 직육면체·정육면체는 면 위에 1×1 칸이 한 칸씩 깔린다(`tileCells`, 정수가 아니면 끝 칸이 좁다) ④ 같은 모양의 나머지 면을 칠한다 식은 왼쪽 쪽에(`pageText`, `가로 4칸 × 세로 3칸 = 12 cm²`). 다음 묶음에서 앞 묶음의 선·칸은 사라진다(`surfaceSteps`). 표기·라벨·색은 ui.md "공식 시각화 규칙". 원기둥·원뿔은 `curvedSurface.ts`: 밑면(반지름, 식) → 옆면이 펼쳐진다(접기와 같은 계산 `sidePoint`, 밑면은 바닥에 남는다). 원기둥은 직사각형이 되며 밑면 둘레였던 변을 강조해 가로 = 2πr. 원뿔은 부채꼴이 되고(호 = 밑면 둘레), 다음 단계에서 반지름이 모선인 큰 원의 나머지를 채워 호 비율(반지름 ÷ 모선)을 보이고 π × 모선 × 반지름. **도형별 설명**: 겉넓이·위치 관계·닮음·부피는 모든 다면체, 대각선·최단 거리는 상자(직육면체·정육면체)만. 겉넓이는 같은 모양 면끼리(변 길이가 같으면 같은 모양) 묶어 칠한다(`surfaceGroups`). 부피는 상자는 단위 정육면체, 각기둥은 밑면 판 층 쌓기, 각뿔·원뿔은 **물 붓기 실험**(`pour.ts`: 물을 담아 들어 올려 기울이면 물줄기가 떨어지고, 같은 밑면·높이의 통이 ⅓·⅔ 눈금까지 찬다. 대상이 초5~중1이라 증명하지 않고 세 번을 눈으로 센다. 물 높이가 보이게 이 설명과 원기둥 원판 쌓기는 카메라를 수평 40°로 낮추고, 끝나면 돌아온다), 정다면체는 면마다 가운데로 모이는 각뿔로 나누기(`solidVolume.ts`). 닮음은 상자는 k배 틀 채우기, 그 밖은 틀 옆에 작은 면 k²장과 작은 도형 k³개 늘어놓기(`similarSolid.ts`, 빈틈없이 채울 수 없는 도형도 되고 나중에 원기둥·원뿔도 같은 방식). 다른 면에 가려져도 보이게 깊이 검사를 끈다(`lengthLabels.ts`). 접기와 같은 방식으로 **뷰어는 `progress` 값만 받고**, 단계·속도·멈춤은 UI가 값을 바꿔서 만든다
  - 구현 위치는 `frontend/src/viewer/lessons/`다. `data.ts`(종류, 단계 수 `lessonStepCount(scene, kind)`, 멈춘 뒤 보여줄 공식 `lessonSummary(scene, kind)`, 화면 물체는 만들지 않음), `index.ts`(`buildLesson(scene, poly, tree, kind, radius)` → `{ group, apply(progress), dispose(), faceMaterials?, bounds?, pickTargets?, pick? }`), 종류마다 파일 하나(`volume.ts`, `surfaceArea.ts`, `pythagoras.ts`, `edgeRelations.ts`, `similar.ts`), 공용 그리기 도우미 `draw.ts`(자라는 막대, 직각 표시). `ThreeViewer`는 `group`을 면 트리 루트(접힌 입체 좌표)에 붙이고 `apply`만 부른다. 면을 따라 접혀야 하는 물체(최단 거리의 선)는 설명이 `tree`의 면 메시에 직접 붙이고 `dispose`에서 뗀다. 설명에 `bounds`(접힌 입체 좌표)가 있으면 카메라가 그 범위를 담는다(닮음처럼 입체 밖에 물체를 두는 설명, 입체 설명과 같이 1.6배 넉넉히). 설명에 `pickTargets`가 있으면 화면을 누를 때 그것을 먼저 맞혀 보고, 맞으면 `pick(target)`을 부른 뒤 다시 적용한다(위치 관계의 기준 모서리 바꾸기, 뷰어 안 상태). 새 설명은 `LessonKind`와 `data.ts`의 표, 종류 파일 하나를 더하면 된다

  - 속표지도 넘기는 종이다: 앞면은 제목, 뒷면은 왼쪽 쪽과 같은 텍스처. **도형은 날아다니다가 속표지가 넘어가기 시작하면 하나씩 흡수된다** (팝업북을 닫으면 팝업이 종이 사이로 접혀 들어가듯)
    - 자리: 도형마다 책등에서 떨어진 정도·방향·높이(1.5~4.2)가 다르다(`SPREAD`, `TWIST`, `HEIGHTS`)
    - 날기: 떠오른 곳을 중심으로 빠르기가 다른 두 곡선을 겹쳐 도형마다 다르게 휘돈다(폭 1.0). 축마다 빠르기가 다른 회전, 세로로 살짝 늘었다 줄었다 하는 말랑한 움직임
    - 흡수 시각: 책등을 축으로 도는 종이가 도형이 떠 있는 방향(책등에서 본 각도 θ)에 닿는 시각을 넘김 각도 식을 거꾸로 풀어 구한다
    - 도형은 바깥 그룹(holder)에 넣는다: holder 가 자리와 늘이기(빨려 가는 방향으로 늘이는 비균일 크기·방향)를, 안쪽 mesh 가 스스로 도는 회전과 크기를 맡는다. 그래서 돌면서도 세계 방향으로 늘어난다
    - 오른쪽에 떠 있던 도형(θ < 90°): **책 가운데(책등 위)가 블랙홀**. 넘어가는 종이가 도형에 닿는 시각까지 1초 동안(넘기자마자 닿는 것도 최소 0.35초), 앞 55%(`REACH`)는 몸은 공중에서 계속 날고 앞끝만 책 가운데까지 길게 늘어나고, 나머지는 몸도 점점 빨라지며 가운데로 빨려 들어가 가늘어지다 사라진다. 책등에서 도형 쪽으로 뻗은 선을 따라 늘어나므로 종이가 그 방향에 닿기 전에 끝나면 종이를 뚫지 않는다. 늘어난 모습이 보이게 속표지는 2.4초에 걸쳐 넘어간다
    - 왼쪽에 떠 있던 도형: 넘기기 시작할 때부터 책등 가까운 것부터 0.06초 간격으로, **바로 아래 왼쪽 쪽으로 가라앉는다**(1초, 물에 잠기듯 처음엔 천천히). 닿으면서 납작하게 퍼지며 종이 속으로 사라진다. 종이가 떠 있던 방향에 닿기 0.15초 전에 끝낸다. 내려갈수록 책등에서 본 각도가 커져 넘어오는 종이에서 멀어진다
  - **그림자**: 오프닝 동안만 그림자를 켠다(`PCFSoftShadowMap`, 지도 2048). 떠 있는 도형과 넘기는 종이만 드리우고 책은 드리우지 않는다. 그래서 끝나고 그림자를 꺼도 빈 책 모습이 같다. 빛은 방향 그대로 책 가운데를 비추게 옮긴다. 도형은 three.js 기본 도형(직육면체, 각기둥, 각뿔, 정다면체, 원기둥, 원뿔)에 모서리 선
  - 시간은 프레임마다 더한다(한 번에 최대 1/30초). 첫 프레임이 늦거나 멈칫해도 단계를 건너뛰지 않는다
- **가려진 모서리** (교과서 겨냥도처럼): 면에 가려 안 보이는 모서리(또는 그 부분)는 점선, 보이는 부분은 실선으로 그린다. 모서리를 두 번 그린다: 실선은 보통 깊이 검사, 점선(`LineDashedMaterial`, `computeLineDistances()`)은 `depthFunc: GreaterDepth`·`depthWrite: false`로 면 뒤에 있는 부분만 보이게 하고 면보다 나중에 그린다(`renderOrder`). 매 프레임 깊이로 정해지므로 화면을 돌리거나 접고 펴도 그때그때 맞다. 보이는 모서리는 면과 깊이가 거의 같아서 그대로 두면 그래픽 카드마다 점선·실선이 깜빡인다. 그래서 실선·점선 모두 **화면 위치는 그대로 두고 깊이만 카메라 쪽으로 도형 크기의 2%만큼 당겨** 그린다(정점 셰이더에서 시선 방향으로 당김, `pullTowardCamera`). 보이는 모서리는 확실히 면 앞이 되고, 가려진 모서리는 면보다 훨씬 뒤라 그대로 점선이다. 실선 모서리는 깊이를 쓰지 않고(`depthWrite: false`) 점선처럼 면을 다 그린 뒤에 그린다(`renderOrder = 1`). 먼저 그리면 나중에 그린 이웃 면에 덮여 펼친 전개도의 접는 선이 끊겨 보인다. 점선 간격은 도형 크기에 비례하게, 촘촘하면 실선처럼 보여 상자가 열린 것처럼 착각되므로 성기게 둔다
- **라이브러리 독립**: `ViewerProps`와 ShapeScene에는 three.js 타입(Mesh, Vector3 등)을 넣지 않는다. 숫자·꼭짓점 인덱스 같은 일반 데이터만 쓴다. 렌더링 라이브러리를 바꿔도 UI와 AI 쪽은 그대로 동작해야 한다

## 다면체 (직육면체, 정육면체, 정다면체): 면 트리

- **면 트리 데이터**: 다면체는 "면 트리"로 표현한다. 면마다 아래 값을 가진다
  - 모양: 꼭짓점 인덱스 목록 (바깥에서 볼 때 반시계 방향 다각형)
  - 부모 면: 루트 면은 없음(고정)
  - 부모와 붙는 모서리: 꼭짓점 인덱스 2개. 이 모서리가 접히는 회전축이다
  - 이면각: 그 모서리에서 부모 면과 이루는 각
- **데이터 위치**: 도형별 면 트리와 꼭짓점 좌표(크기를 받아 계산)는 `frontend/src/viewer/polyhedra.ts` 한 파일에 모은다. 새 다면체는 이 파일에 데이터를 추가하는 것만으로 지원되어야 한다 (렌더링 코드는 도형 이름으로 분기하지 않는다)
- **구현 위치**: 면 트리 → three.js 계층은 `frontend/src/viewer/faceTree.ts`의 `buildFaceTree`, 펼침 값 적용은 `applyUnfold(tree, s)`다. 회전 방향은 데이터에 적지 않고, "다 펼쳤을 때 면의 바깥 법선이 부모 면의 바깥 법선과 같아지는 쪽"으로 자동으로 정한다. `npm test`가 직육면체·정육면체의 `s = 0`(입체)과 `s = 1`(cross 배치)을 검사하고, `layOnFloor` 후에는 `s = 1`이면 모든 면이 y = 0에 바깥 면을 아래로 두고, `s = 0`이면 바닥 위(y ≥ 0)에 있는지 검사한다. 단계별 접기는 `foldOrder`가 올바른지, 단계 경계마다 순서대로 면이 접혔는지(자기와 조상이 모두 접힌 면은 입체 좌표), 직육면체 순서가 왼쪽 → 뒷면 → 오른쪽 → 윗면 → 아랫면인지 검사한다
- **계층과 접기**: 면마다 부모와 붙는 모서리 위치에 pivot `Group`을 두고, 면 메시를 그 안에 배치한다. 각 pivot의 회전각은 접힌 상태 기준 **`s × (180° − 이면각)`** 이다. `s = 1`이면 모든 면이 루트 면과 같은 평면에 놓여 전개도가 된다
- **직육면체의 면 트리**: 이면각은 모두 90°라서 회전각은 `s × 90°`다. 펼친 모양이 [shape-scene.md](shape-scene.md)의 `cross`가 된다

  | 면 (꼭짓점) | 부모 | 붙는 모서리 | 이면각 |
  |---|---|---|---|
  | 앞면 (0-1-5-4) | 없음 (루트) | - | - |
  | 왼쪽 (0-4-7-3) | 앞면 | 0-4 | 90° |
  | 오른쪽 (1-2-6-5) | 앞면 | 1-5 | 90° |
  | 윗면 (4-5-6-7) | 앞면 | 4-5 | 90° |
  | 아랫면 (0-3-2-1) | 앞면 | 0-1 | 90° |
  | 뒷면 (3-7-6-2) | 오른쪽 | 2-6 | 90° |

- **단계별 접기** (`foldMode = 'step'`, [ui.md](ui.md) 친절한 설명 원칙)
  - **순서 데이터**: 면 트리 데이터에 접는 순서 `foldOrder`(루트가 아닌 면 인덱스 목록)를 둔다. 없으면(정다면체) **처음 카메라에서 먼 면부터** 접는다(`farFirstOrder`). 이때 전개도는 바닥에 눕힐 때 세로축으로 돌려서, 펼친 전개도의 가운데가 루트 면보다 카메라에서 먼 쪽에 오게 한다(`facingYaw`, `layOnFloor(tree, poly, yaw)`). 그래서 루트 쪽은 카메라 앞 바닥에 남고, 먼 쪽이 먼저 일어서도 가까운 면이 접히는 모습을 가리지 않는다. `foldOrder`가 있는 도형(직육면체·정육면체, 학습지 전개도)은 돌리지 않는다(학습지 사진과 위치가 맞아야 해서). 루트가 아닌 면을 한 번씩 담으면 되고, 자식 면이 부모보다 먼저 와도 된다 (`npm test`가 검사). 직육면체 기본 순서는 **왼쪽 → 뒷면 → 오른쪽 → 윗면 → 아랫면**이다. 뒷면이 먼저 오른쪽 면 끝에서 일어서고, 그다음 오른쪽 면이 접히며 뒷면을 덮개처럼 얹는다. 오른쪽 면을 먼저 접으면 펴진 뒷면이 위로 길게 솟아서(직육면체 4×2×3 기준 높이 6, 이 순서는 약 4.5) 화면을 더 넓게 잡아야 한다
  - **면마다 진행률**: 단계 수 `n`, 접힘 `f = 1 − s`일 때 순서의 `k`번째 면은 `clamp(f × n − k, 0, 1)`만큼 접힌다. 즉 슬라이더 전체가 `n`칸으로 나뉘고 한 칸에 면 하나가 접힌다. 계산은 `faceTree.ts`의 `stepUnfold(order, faceCount, s)`이고, `applyUnfold(tree, s)`는 숫자 하나 또는 면마다의 값 배열을 받는다
  - **강조**: 지금 접히는 면(진행률이 0과 1 사이)은 강조색, 나머지 면은 연하게, 그 면의 회전축 모서리는 굵게 그린다. 단계 사이에 멈춰 있을 때는 마지막에 움직인 면을 계속 강조하고, 다 펼치거나 다 접으면 강조를 끈다
  - **단계 사이 멈춤·속도·이징**은 UI가 `unfold`를 바꾸는 방식으로 만든다. 뷰어는 값만 받는다
  - **카메라 범위**: 접는 중간 모양(오른쪽 면이 접히며 뒷면을 들어 올리는 순간 등)이 다 접은 모양보다 높이 솟아서, 카메라 범위는 두 방식의 중간 모양까지 담는다. 한 단계를 8칸으로 나눠 그 모양들을 모두 담는다. 방식을 바꿔도 카메라는 움직이지 않는다
- **정다면체 이면각**: 정사면체 약 70.53°, 정육면체 90°, 정팔면체 약 109.47°, 정십이면체 약 116.57°, 정이십면체 약 138.19°. 각 도형의 면 트리(기본 전개도)는 `polyhedra.ts`에 정의한다 (TODO-16)
  - 좌표는 가운데가 원점이고 [shape-scene.md](shape-scene.md) 꼭짓점 규칙을 따른다. 면의 꼭짓점 순서(바깥에서 반시계)는 꼭짓점 집합에서 계산한다(`ccw`)
  - 기본 전개도는 교과서 모양: 정사면체는 밑면 둘레에 옆면 셋(큰 정삼각형), 정팔면체는 꼭대기 둘레 윗면 넷을 부채꼴로 + 각 윗면 바깥에 아랫면, 정십이면체는 윗면 꽃(윗면 + 둘레 다섯)과 아랫면 꽃을 꽃잎 하나로 이음, 정이십면체는 가운데 띠 10개 한 줄 + 위 뚜껑 5개는 띠 위쪽, 아래 뚜껑 5개는 띠 아래쪽(띠 가운데 면이 루트)
  - 회전 방향은 두 방향을 모두 돌려 보고 부모 법선에 더 가까운 쪽이다. 이면각이 135°보다 크면(정이십면체) 반대 방향도 내적이 양수라 "내적 > 0"으로는 가를 수 없다
  - `npm test`가 4종 모두 접힌 좌표, 펼치면 바닥 한 평면에 면끼리 겹치지 않음, 맞닿는 모서리 쌍 수(3·5·19·11), 닫힘을 검사한다
- **각기둥·각뿔의 면 트리** (TODO-31, 밑면 정다각형, `polyhedra.ts`의 `prism`·`pyramid`): 이면각은 데이터에 적지 않고 좌표에서 구한다(180° − 두 면 바깥 법선 사이 각, 정다면체도 같은 함수 `solid`)
  - 각기둥: 직육면체처럼 앞 옆면(0-1)이 루트, 옆면을 한 줄로(오른쪽에 ⌈(n−1)/2⌉개, 왼쪽에 나머지), 윗면·밑면은 앞 옆면에 붙는다. `foldOrder`는 직육면체 규칙과 같게 왼쪽 줄(먼 것부터) → 오른쪽 줄(먼 것부터) → 윗면 → 밑면 (사각기둥이면 직육면체와 같은 순서)
  - 각뿔: 밑면이 루트, 밑면 둘레에 옆면 삼각형(별 모양). `foldOrder` 없음 → 카메라에서 먼 옆면부터
  - `npm test`가 삼각·오각·육각기둥, 삼각·사각·칠각뿔의 접힌 좌표, 펼친 면 겹침 없음, 맞닿는 모서리 쌍 수(각기둥 2n−1, 각뿔 n), 닫힘, 접는 순서를 검사한다
- **선분**: 선분은 그 선분이 놓인 면 메시의 **자식**으로 붙인다. 끝점은 면 기준 좌표로 계산한다 (`{ vertex }` → 그 꼭짓점, `{ edge: [i, j], t }` → i에서 j 쪽으로 t만큼). 그러면 면이 접힐 때 선이 자동으로 따라온다. 원래 입체 좌표로 그린 선은 따라오지 않는다
  - **면 고르기**: `{ vertex: v }`는 v를 가진 면, `{ edge: [i, j] }`는 i-j가 **그 면의 모서리**인 면이어야 한다. 두 끝점을 모두 만족하는 면이 여럿이면(선분이 모서리와 겹칠 때) 면 인덱스가 가장 작은 면에 붙인다. 계산은 `faceTree.ts`의 `placeLines(poly, lines)`이고 `npm test`가 검사한다
  - **그리기**: WebGL 선은 굵기가 1px로 고정이라, 선분은 도형 크기에 비례한 가는 원기둥(반지름 = 카메라 범위 반지름의 1%)으로 그린다. 원기둥 중심이 면 위에 있어서 면 바깥(입체)과 안쪽(바닥에 눕힌 전개도) 어느 쪽에서도 보인다. 양 끝은 굵기만큼 줄여 꼭짓점·모서리에서 입체 밖으로 삐져나오지 않게 한다. 색은 [ui.md](ui.md)의 "면 위 선분". 면에 가려진 선분(특히 다 접은 상자의 바닥에 그은 선)은 가려진 모서리처럼 옅은 분홍 점선으로 비쳐 보인다. 선분마다 같은 자리에 1px 점선(`LineDashedMaterial`, `GreaterDepth`, 깊이만 카메라 쪽으로 당김)을 하나 더 그리고, 면을 다 그린 뒤에 그린다. 당기는 거리(도형 크기의 2%)가 원기둥 굵기(1%)보다 커서 보이는 선분에는 점선이 끼지 않는다. `showHiddenEdges`를 따른다
- **두 면에 걸친 선**: ShapeScene에서 면별 선분으로 나눠서 표현한다 (계약 그대로). 선 긋기로 다른 면의 두 점을 이으면 뷰어가 이렇게 나눠서 더한다. 펼치면 잘린 모서리에서 끊어지는 게 맞다 (전개도에서 이웃한 면 사이는 이어져 보인다). 두 끝점이 같은 면 위에 없는 선분은 그리지 않고 콘솔에 경고한다
- **꼭짓점 복사본**: 각 면은 자기 꼭짓점들의 표시점을 자식으로 가진다. 전개도에서 꼭짓점의 복사본은 `(면, 꼭짓점 인덱스)` 쌍이다. 펼치면 한 꼭짓점이 여러 곳(직육면체는 최대 3곳)으로 나뉜다. 라벨·색·하이라이트는 "꼭짓점 인덱스가 같은 복사본 모두"에 적용한다
  - 각 면 메시는 꼭짓점마다 표시점(작은 구)과 라벨(Sprite, `vertexLabels`가 `null`이거나 한글이 들어 있으면 없음, [ui.md](ui.md) "라벨")을 자식으로 가진다. 둘 다 꼭짓점 위치에 두어서 다 접으면 복사본이 한 자리에 겹쳐 하나로 보인다. 라벨은 모서리 선처럼 깊이만 카메라 쪽으로 당겨(`pullTowardCamera`) 자기 면에 잘리지 않고, 앞의 면에 가려진 꼭짓점의 라벨은 가려진다
  - **색은 고를 때만**: 평소에는 표시점은 진한 회색, 라벨은 진한 글씨다 (진한 색은 맞닿는 모서리에 쓰므로, [ui.md](ui.md)). 꼭짓점을 누르거나 `highlightVertices`가 들어오면 그 꼭짓점의 복사본이 모두 같은 색(맞닿는 모서리와 같은 7색을 목록 순서대로)으로 크게, 나머지 꼭짓점은 흐리게 바뀐다. 같은 꼭짓점을 다시 누르거나 빈 곳을 누르면 풀린다. 꼭짓점을 누르면 고른 모서리 쌍은 풀리고, 그 반대도 같다
- **맞닿는 모서리**: 면 트리에서 부모-자식으로 붙어 있지 않은 모서리는 전개도에서 잘린 모서리이고, 같은 두 꼭짓점을 가진 잘린 모서리 두 개가 접으면 맞닿는 한 쌍이다 (직육면체는 7쌍). 쌍마다 색을 하나 정해 두 모서리를 같은 색으로 칠한다. 면에는 이 색을 쓰지 않는다 ([ui.md](ui.md))
  - 계산은 `polyhedra.ts`의 `matchingEdges(poly)`(three.js 없음)이고 결과는 쌍마다 `[면, [꼭짓점, 꼭짓점]]` 두 개다. 도형 이름으로 분기하지 않는다. `npm test`가 직육면체·정육면체 7쌍(붙는 모서리 5개 + 7쌍 = 모서리 12개)을 검사한다
  - 색칠한 모서리는 1px 선 대신 가는 원기둥으로 그려(기본 모서리보다 눈에 띄게) 그 면 메시의 자식으로 붙인다. 그래서 접힐 때 따라오고, 다 접으면 두 모서리가 한 자리에 겹친다. 색은 [ui.md](ui.md)의 7색을 쌍 순서대로 쓰고 쌍이 더 많으면(정다면체) 돌려 쓴다
  - **고르기**: 색칠한 모서리를 누르면(끌지 않고 클릭) 그 쌍의 두 모서리가 함께 굵어진다. 같은 모서리를 다시 누르거나 빈 곳을 누르면 풀린다. 고른 쌍은 뷰어 안 상태라서 `ViewerProps`에 넣지 않는다
- **선 긋기** (`drawLines`, TODO-6)
  - **등분점**: 각 면의 모서리마다 `edgeDivisions` n에 따라 k/n 위치(양 끝 제외)에 작은 표시점을 둔다. 선 긋기 모드에서만 보인다. 면의 꼭짓점 순서대로 a→b 모서리 위 점은 `{ edge: [a, b], t: k/n }`이다. 면마다 고를 수 있는 점(꼭짓점 + 등분점) 목록은 `faceTree.ts`의 `facePoints(poly, face, n)`이고 `npm test`가 검사한다
  - **점 고르기**: 표시점마다 클릭 영역을 두면 짧은 모서리에서 영역이 겹치고, 다 접으면 꼭짓점 복사본이 한 자리에 겹친다. 그래서 표시점마다 클릭 영역을 두지 않고, **화면 픽셀 기준**으로 누른 곳에서 반지름 28px 안의 가장 가까운 점을 고른다(확대·축소와 상관없이 같은 크기, 손가락 터치 영역 정도). 면 뒤에 가려진 점은 고르지 않는다(카메라에서 그 점까지 사이에 다른 면이 있는지 `Raycaster`로 본다). 거리가 같으면(다 접어 겹친 꼭짓점 복사본) 누른 곳에 맞은 면의 복사본을 고른다. 면 바깥을 살짝 눌러도 28px 안에 점이 있으면 고른다. 면 가운데처럼 가까운 점이 없으면 무시하고, 도형 밖을 누르면 고른 점이 풀린다
  - **긋기**: 첫 점은 선분 색의 큰 점으로 보인다. 같은 점을 다시 누르면 풀린다. 둘째 점을 누르면

## 전개도 grid (학습지 전개도 그대로, 이슈 #67)

직육면체·정육면체의 `net.layout = "grid"`([shape-scene.md](shape-scene.md))는 펼친 전개도가 데이터다. 뷰어가 전개도를 접어 면 트리 데이터(`Polyhedron`)를 만들고, 그 뒤로는 다른 다면체와 똑같이 그린다(접기, 단계별 접기, 가려진 모서리, 맞닿는 모서리, 선 긋기).

- **접어서 면 트리 만들기**: `gridNet.ts`의 `gridPolyhedron(net)`(three.js 없음). `polyhedronOf(scene)`가 grid면 이것을 부른다. `npm test`가 십자형 grid(닫힘, 꼭짓점 8, 맞닿는 모서리 7쌍), 계단형(닫힘), 잘못 그린 전개도(겹친 면 2개), 전개도 위 선·라벨·면 표시를 검사한다
  - 두 면의 변이 같은 직선 위에서 겹치면 이웃이다. 이웃이 가장 많은 면을 루트로 너비 우선으로 면 트리를 만든다(사이클이 있으면 먼저 닿은 쪽만 경첩)
  - 모든 면을 부모에 대해 **같은 쪽으로 90°** 접는다. 접은 위치에서 같은 자리에 온 꼭짓점은 하나로 합친다. 이면각은 모두 90°이고 단계별 접기 순서는 너비 우선 순서다
  - 전개도의 면 꼭짓점 → (면, 꼭짓점 번호) 대응을 같이 돌려줘서 `cornerLabels`와 전개도 위 `lines`를 면에 붙인다. 전개도 위 선은 면마다 잘라(축에 나란한 직사각형과 선분 자르기) 면 위 선분으로 바꾼다. 끝점이 면 변 위에 없는 조각은 버리고 경고한다
- **바른 전개도인지**(`netCheck(scene)`, `index.ts`에서 export): 다 접었을 때 ① 같은 자리에 겹친 면이 없고 ② 잘린 모서리가 모두 짝을 이루면 닫힌 입체다. 아니면 겹친 면(같은 자리·같은 방향)을 돌려준다. UI가 상태 배지에 쓴다
  - 잘못된 전개도는 다 접힌 쪽(접기 90% 이상)에서 겹친 면을 연한 빨강으로 칠한다
- **꼭짓점 라벨**: `cornerLabels`는 복사본마다 다른 글자라서 꼭짓점마다 라벨 하나(`vertexLabels`)가 아니라 **(면, 꼭짓점) 복사본마다** 라벨 Sprite를 붙인다. 문제 풀이에 꼭 필요한 라벨이라 한글 기호도 보인다([ui.md](ui.md) "라벨"). "꼭짓점 라벨" 보기 옵션을 따른다
- **면 표시**: `fill`인 면은 색칠 색, `text`는 면 가운데에 글자를 그린 얇은 판(양면, 면에서 아주 조금 띄움)을 면 메시의 자식으로 붙인다. 접으면 따라간다
- **다른 전개도 모양** (TODO-38): `gridNet.ts`의 `NET_VARIANTS`(정육면체 전개도 11가지, 단위 정사각형 칸 목록, 첫째는 십자형)와 `netVariant(k, [가로, 세로, 높이])`(three.js 없음, `index.ts`에서 export)가 k번째 모양을 그 치수의 grid 면 목록으로 만든다. 도형 이름으로 분기하지 않고, 칸을 너비 우선으로 따라가며 면의 가로·세로·법선이 입체의 어느 방향인지 들고 다닌다: 루트 칸은 가로 = 가로, 세로 = 높이, 법선 = 세로(십자형 앞면과 같음). 왼쪽·오른쪽으로 넘어가면 면의 가로와 법선이, 위·아래로 넘어가면 세로와 법선이 서로 바뀐다. 면 크기는 그 방향의 길이이고, 부모 면 옆에 맞닿는 변을 맞춰 놓는다. `npm test`가 11가지 모두 정육면체와 직육면체(서로 다른 세 치수 여러 개) 치수로 `netCheck` 닫힘, 면끼리 겹치지 않음, 접은 크기가 치수와 같음을 검사하고, 11가지가 돌리거나 뒤집어도 서로 다른 모양인지 검사한다

## 곡면 도형 (원기둥, 원뿔)

- **모듈 분리**: 곡면 도형은 면 트리를 쓰지 않고 별도 모듈 `frontend/src/viewer/curved.ts`에 둔다
- **말기**: 옆면을 전개도(직사각형·부채꼴) 위의 격자 정점으로 만들고, `s`에 따라 각 정점을 평면(전개도) ↔ 곡면 위치 사이로 보간해서 말린다. 길이가 늘거나 줄지 않도록 위치를 직선으로 섞지 말고 **굽힌 정도를 보간**한다
  - 원기둥: 반지름 `radius / (1 − s)`인 원기둥에 감는다 (`s = 1`이면 평면)
  - 원뿔: 모선 길이는 그대로 두고, 밑면 반지름을 `radius`에서 모선 길이까지 `s`에 비례해 늘린 원뿔에 감는다 (모선 길이와 같아지면 평면)
- **밑면 원**: 옆면 전개도의 한 점([shape-scene.md](shape-scene.md)의 곡면 전개도)에 붙어 있고, 그 점의 접선을 축으로 돈다. 다 접으면 원기둥은 90°, 원뿔은 90° + 기울기(`asin(radius / L)`)를 돈다. 원뿔을 90°만 돌리면 호와 원 둘레가 맞지 않는다. 화면에서는 밑면 원(원기둥은 앞쪽 원)을 바닥에 두고 옆면이 일어선다(다면체의 루트 면과 같음). 그래서 다 접으면 똑바로 선 입체가 된다
- **화면**: `CurvedViewer.tsx`가 같은 책·카메라·왼쪽 쪽 메뉴를 쓰고, `Viewer.tsx`가 도형에 맞는 화면을 고른다. 자른 선 둘, 둘레와 원은 만나는 것끼리 같은 색이다(`showMatchingEdges`). 단계별 접기는 없다(`foldStepCount` 0). 공식 설명은 말아 둔 도형 대신 바로 세운 입체에 그린다(`lessons/curvedLessons.ts`): 겉넓이 밑면 → 옆면, 부피는 원기둥 원판 쌓기(점선 틀을 처음부터 보인다)·원뿔 물 붓기 실험, 닮음은 틀 옆에 밑면 k²장·도형 k³개. `npm test`(`curved.test.ts`)가 평면·입체, 길이가 그대로인지, 둘레와 원이 맞닿는지 검사한다. 곡면 위 선과 `net.seam`은 아직 화면에 영향이 없다(TODO-19·20)
- **곡면 위 선** (`curved.ts`의 `curvedLinePoints`, `scene.lines`): 선은 **전개도 위의 직선**이다. 전개도 좌표에서 직선을 잘게 나눈 점들(64개)에 옆면과 같은 변환을 적용해서 그린다. 그래서 말릴 때 곡면을 따라 휘어 감긴다. 화면에서 긋는 입력은 두지 않는다(곡면에서 쓸 선이 실 감기 정도라 지웠다, 리포트 T19). 사진 인식이나 `scene.lines`로 들어온 선만 그린다

### 무대 (`viewer/stage.ts`)

```ts
buildStage(scene: ShapeScene, theme: Theme3D): Stage | null
stageSupported(scene: ShapeScene): boolean // 다면체(면 트리, 면 2개 이상), 원기둥·원뿔, 구. 면이 하나뿐인 학습지(전개도 고르기)나 모르는 도형은 false

interface Stage {
  object: THREE.Group // 바닥(y = 0)에 놓인 도형. 원점 = 다 접은 입체의 수평 가운데
  steps: number // 단계별 접기 단계 수. 0 이면 한 번에만 접힌다 (원기둥·원뿔) 또는 접지 않는다 (구)
  foldable: boolean // 구는 false
  apply(s: number, mode?: 'all' | 'step'): void // s: 0 = 입체, 1 = 전개도
  solid: THREE.Box3 // 다 접은 입체의 범위
  all: THREE.Box3 // 접고 펴는 동안 차지하는 전체 범위
  resize(width: number, height: number): void // 굵은 선을 그리는 화면 크기 (기기 픽셀)
  dispose(): void
}
```

- 다면체: 책 장면과 같은 면 트리(`buildFaceTree`·`applyUnfold`·`stepUnfold`), 같은 자세(`layOnFloor`, 순서가 없는 도형은 `facingYaw`), 같은 접는 순서(`foldOrderOf`, 없으면 `farFirstOrder`). 굵은 선 테마면 모서리를 `Line2`로 덧그린다
- 원기둥·원뿔: 책 장면과 같은 `buildCurvedNet`에 토큰 색을 넘긴다. 맞닿는 선 색은 켠다. 선 관 굵기는 굵은 선 테마에서 두 배
- 구: 책 장면과 같은 `buildSphereBody`. 접지 않는다
- 자리 잡기: 다 접은 입체의 가장 낮은 곳을 y = 0, 수평 가운데를 원점에 둔다. 그래서 세로축으로 돌리면 제자리에서 돈다
- 범위는 꼭짓점으로 잰다 (`boundsOf`). `Box3.expandByObject`는 기울어진 면의 상자를 다시 돌려 담아서 실제보다 크다: 펼친 전개도에 두께가 생기고 정팔면체가 바닥 아래로 내려가 보인다. 인스턴스로 그린 관(곡면 선)은 조각마다 잰다
- 검사: `stage.test.ts`. 모든 도형 종류(`ShapeKind`마다 기본 치수 표, 도형 종류가 늘면 표가 없어 타입 검사가 실패한다) × 두 테마, 실제 학습지 13장의 정답 도형(`worksheetScenes.ts`, `backend/evals/answers.json`에서 복사). 단계 수, 바닥·가운데, 전체 범위가 입체와 전개도를 담는지, 다면체 전개도가 바닥에 납작한지, 면 1개 학습지는 홀로그램 불가, 토큰 이름이 같은지와 홀로그램 선이 밝은지

### `HologramViewer` (`frontend/src/viewer/HologramViewer.tsx`)

`viewer/index.ts`에서 export한다. `ViewerProps`와 따로인 컴포넌트다 (책 장면 `Viewer`는 그대로).

| prop | 기본 | 뜻 | 바뀌면 |
|---|---|---|---|
| `scene: ShapeScene` | | 그릴 도형. 무대가 그리는 도형 (`hologramSupported` = `stageSupported`) | 다시 만든다 |
| `center?: number` | `0.2` | 가운데 정사각형 한 변 ÷ 화면 짧은 변 = 피라미드 꼭지 크기. **기기마다 다른 유일한 값** | 칸만 다시 배치 |
| `showGuide?: boolean` | `false` | 가운데 정사각형 테두리(피라미드 놓을 자리). 가운데를 맞출 때만 켠다 | 칸만 다시 배치 |
| `onTap?: () => void` | | 화면을 누르면 | |

나머지는 고정값이다 (간소화, 2026-10-31 사용자 결정): 카메라 높이각 20°(펼칠수록 45°), 늘 천천히 돌기(0.35 rad/s), 늘 접었다 펴기 반복, 좌우 반전 없음. 좌우 반전이 틀려도 도형이 대칭이고 글자를 그리지 않아 눈에 띄지 않는다

`hologramSupported(scene)` (= `stageSupported`): 직육면체·정육면체·정다면체 4종·각기둥·각뿔(학습지 grid 전개도 포함, 면 2개 이상), 원기둥·원뿔, 구. 잘못 그린 전개도도 그대로 접혀 보인다 (닫히지 않아도 된다).

홀로그램은 도형을 모른다. `buildStage(scene, HOLOGRAM)`이 준 물체를 세로축으로 돌리고, 범위(`solid`·`all`)로 카메라 거리를 정하고, `apply`로 접는다.

#### 화면 배치 (`holoLayout.ts`, three.js 없음)

- 좌표: 컨테이너 가운데가 원점, x 오른쪽, y 위 (픽셀)
- L = 컨테이너 짧은 변, c = `center` × L
- 가운데 c × c 정사각형은 검게 둔다. 둘레를 대각선으로 나눈 사다리꼴 4칸: 아래·오른쪽·위·왼쪽 (`regions(L, c)`)
- 칸마다 카메라 하나. 그 칸 쪽에 선 사람이 그 방향의 모습을 본다

| 칸 | 바깥 방향 | 카메라 (방위각) | 그 사람의 오른쪽 |
|---|---|---|---|
| 아래 | −y | 앞 +z (0) | +x |
| 오른쪽 | +x | 오른쪽 +x (π/2) | +y |
| 위 | +y | 뒤 −z (π) | −x |
| 왼쪽 | −x | 왼쪽 −x (−π/2) | −y |

- 반사 규칙 (뒤집은 피라미드, 45° 면): 칸의 **바깥쪽이 떠 보이는 도형의 위쪽**이다. 좌우는 그 칸 쪽에 선 사람의 오른쪽이 그림 오른쪽이다 (거울 면은 면과 나란한 방향을 바꾸지 않는다). `uvOf(region, L, c, p)`
- 렌더링: 칸마다 `WebGLRenderTarget`(가로 L × 세로 (L − c)/2, 기기 픽셀)에 그리고, 사다리꼴 메시에 텍스처로 붙인다. 사다리꼴 밖은 잘린다. 해상도 배율은 2까지 (휴대폰에서 한 프레임에 4번 그린다)
- 크기 맞추기 `fitDistance`: 도형이 돌고 접히는 동안 차지하는 구(반지름 R)가 칸 가운데 높이의 사다리꼴 폭 (c + L)/2와 그림 세로 중 작은 쪽의 95%에 들어가게 카메라 거리를 정한다. 세로 시야각 35°

#### 움직임

- 반복: 펼친 채 1.5초 → 접기 (단계가 있으면 한 면씩 면당 0.9초, 원기둥·원뿔은 한 번에 3초) → 접힌 채 4초 → 한 번에 펼치기 1.5초. 구는 접지 않고 돌기만 한다
- 돌리는 축은 무대의 원점(다 접은 입체의 수평 가운데)이다
- 다 접히면 카메라가 입체 범위(`solid`)로 다가가 입체 가운데 높이를 본다. 펼칠수록 전체 범위(`all`)로 물러나고, 높이각이 45°까지 올라가고, 보는 높이가 바닥으로 내려간다. 바닥에 누운 전개도가 납작하지 않고, 넓은 전개도가 칸의 넓은 가운데에 와서 좁은 안쪽 변에서 잘리지 않게
- 보이는 모습은 `HOLOGRAM` 토큰. 꼭짓점 라벨·선·면 표시는 그리지 않는다 (작은 피라미드에서 읽히지 않는다)
