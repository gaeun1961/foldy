## B. 구현 규칙

- **LLM 호출은 전부 backend에서** 한다. API 키(`LLM_API_KEY`)가 브라우저에 노출되면 안 되므로 frontend에서 LLM을 직접 호출하지 않는다
- 비전 LLM은 사진을 ShapeScene JSON으로 바꾸고, 결과는 `ShapeScene.model_validate`로 검증한다. 인식에 실패하면 사용자가 도형·치수를 직접 입력하는 **수동 경로**가 반드시 있어야 한다
- 비전 LLM 연결 위치는 `backend/app/ai/vision.py`의 `analyze_image`, 챗봇 연결 위치는 `backend/app/ai/chat.py`의 `reply`다. `backend/app/api/`의 라우터는 이 함수들을 부르기만 한다
- **뷰어는 인터페이스 뒤에 숨긴다**. UI는 `frontend/src/viewer/index.ts`의 `Viewer`와 `ViewerProps`만 사용하고, 구현을 바꿀 때는 이 파일의 export 한 줄만 교체한다
- AI 기능이 붙기 전에는 목 데이터를 쓴다. frontend는 `frontend/src/shared/mock.ts`, backend는 `backend/app/ai/vision.py`의 `MOCK_SCENE`이며, 둘은 같은 내용을 유지한다
- CORS는 Vite 개발 서버(`http://localhost:5173`, `http://127.0.0.1:5173`)만 허용한다

### three.js 뷰어 규칙

TODO-1의 GeoGebra 실험(`frontend/lab/geogebra.ts`, 서비스에 쓰지 않음)에서 확인한 배치·동작을 three.js로 직접 구현한다.

#### 공통

- **좌표**: three.js는 y가 위다. 도형 중심이 원점이고 x = 가로, y = 높이, z = 깊이(앞면이 +z 쪽, 보는 사람 쪽)다. C의 꼭짓점 규칙과 같은 위치다
- **펼침 값 `s`**: 모든 도형에서 0 = 입체(접힘·말림), 1 = 전개도(펼침)
- **라이브러리 독립**: `ViewerProps`와 ShapeScene에는 three.js 타입(Mesh, Vector3 등)을 넣지 않는다. 숫자·꼭짓점 인덱스 같은 일반 데이터만 쓴다. 렌더링 라이브러리를 바꿔도 UI와 AI 쪽은 그대로 동작해야 한다

#### 다면체 (직육면체, 정육면체, 정다면체): 면 트리

- **면 트리 데이터**: 다면체는 "면 트리"로 표현한다. 면마다 아래 값을 가진다
  - 모양: 꼭짓점 인덱스 목록 (바깥에서 볼 때 반시계 방향 다각형)
  - 부모 면: 루트 면은 없음(고정)
  - 부모와 붙는 모서리: 꼭짓점 인덱스 2개. 이 모서리가 접히는 회전축이다
  - 이면각: 그 모서리에서 부모 면과 이루는 각
- **데이터 위치**: 도형별 면 트리와 꼭짓점 좌표(크기를 받아 계산)는 `frontend/src/viewer/polyhedra.ts` 한 파일에 모은다. 새 다면체는 이 파일에 데이터를 추가하는 것만으로 지원되어야 한다 (렌더링 코드는 도형 이름으로 분기하지 않는다)
- **계층과 접기**: 면마다 부모와 붙는 모서리 위치에 pivot `Group`을 두고, 면 메시를 그 안에 배치한다. 각 pivot의 회전각은 접힌 상태 기준 **`s × (180° − 이면각)`** 이다. `s = 1`이면 모든 면이 루트 면과 같은 평면에 놓여 전개도가 된다
- **직육면체의 면 트리**: 이면각은 모두 90°라서 회전각은 `s × 90°`다. 펼친 모양이 C의 `cross`가 된다

  | 면 (꼭짓점) | 부모 | 붙는 모서리 | 이면각 |
  |---|---|---|---|
  | 앞면 (0-1-5-4) | 없음 (루트) | - | - |
  | 왼쪽 (0-4-7-3) | 앞면 | 0-4 | 90° |
  | 오른쪽 (1-2-6-5) | 앞면 | 1-5 | 90° |
  | 윗면 (4-5-6-7) | 앞면 | 4-5 | 90° |
  | 아랫면 (0-3-2-1) | 앞면 | 0-1 | 90° |
  | 뒷면 (3-7-6-2) | 오른쪽 | 2-6 | 90° |

- **정다면체 이면각**: 정사면체 약 70.53°, 정육면체 90°, 정팔면체 약 109.47°, 정십이면체 약 116.57°, 정이십면체 약 138.19°. 각 도형의 면 트리(기본 전개도)는 `polyhedra.ts`에 정의한다
- **선분**: 선분은 그 선분이 놓인 면 메시의 **자식**으로 붙인다. 끝점은 면 기준 좌표로 계산한다 (`{ vertex }` → 그 꼭짓점, `{ edge: [i, j], t }` → i에서 j 쪽으로 t만큼). 그러면 면이 접힐 때 선이 자동으로 따라온다. 원래 입체 좌표로 그린 선은 따라오지 않는다
- **두 면에 걸친 선**: ShapeScene에서 면별 선분으로 나눠서 표현한다 (계약 그대로). 펼치면 잘린 모서리에서 끊어지는 게 맞다. 두 끝점이 같은 면 위에 없는 선분은 그리지 않고 콘솔에 경고한다
- **꼭짓점 복사본**: 각 면은 자기 꼭짓점들의 표시점을 자식으로 가진다. 전개도에서 꼭짓점의 복사본은 `(면, 꼭짓점 인덱스)` 쌍이다. 펼치면 한 꼭짓점이 여러 곳(직육면체는 최대 3곳)으로 나뉜다. 라벨·색·하이라이트는 "꼭짓점 인덱스가 같은 복사본 모두"에 적용한다
- **클릭**: `Raycaster`로 꼭짓점 표시점과 모서리 중점 표시점을 맞힌다. 결과는 `(면, { vertex })` 또는 `(면, { edge, t: 0.5 })`이고, 선 긋기에서 같은 면인지는 이 면 정보로 판단한다

#### 곡면 도형 (원기둥, 원뿔)

- **모듈 분리**: 곡면 도형은 면 트리를 쓰지 않고 별도 모듈 `frontend/src/viewer/curved.ts`에 둔다
- **말기**: 옆면을 전개도(직사각형·부채꼴) 위의 격자 정점으로 만들고, `s`에 따라 각 정점을 평면(전개도) ↔ 곡면 위치 사이로 보간해서 말린다. 길이가 늘거나 줄지 않도록 위치를 직선으로 섞지 말고 **굽힌 정도를 보간**한다
  - 원기둥: 반지름 `radius / (1 − s)`인 원기둥에 감는다 (`s = 1`이면 평면)
  - 원뿔: 모선 길이는 그대로 두고, 밑면 반지름을 `radius`에서 모선 길이까지 `s`에 비례해 늘린 원뿔에 감는다 (모선 길이와 같아지면 평면)
- **밑면 원**: 옆면 전개도의 한 점(C의 전개도 규칙)에 붙어 있고, 그 점의 접선을 축으로 `s × 90°` 회전한다
- **곡면 위 선**: 선은 **전개도 위의 직선**이다. 전개도 좌표에서 직선을 잘게 나눈 점들(예: 64개)에 옆면과 같은 보간 변환을 적용해서 그린다. 그래서 말릴 때 곡면을 따라 휘어 감긴다
- **곡면 선 입력**: 곡면 도형의 선은 전개도 상태(`s = 1`)에서 클릭으로 받는다. 클릭한 위치를 C의 전개도 좌표로 바꿔 끝점을 만든다

## C. ShapeScene 데이터 계약

AI(사진 인식)는 ShapeScene JSON을 **만들고**, 뷰어·UI는 그것을 **그리기만** 한다.
이 형식만 지키면 서로를 기다리지 않고 작업할 수 있다.

- TypeScript: [frontend/src/shared/types.ts](../frontend/src/shared/types.ts)
- Python(Pydantic): [backend/app/ai/schema.py](../backend/app/ai/schema.py)
- 두 파일은 항상 같은 구조여야 한다. **변경은 GitHub 이슈로 먼저 합의하고, 이 문서부터 고친 뒤** 두 파일과 목 데이터를 같은 PR에서 함께 고친다.

### 필드

`shape`에 따라 `size`, `vertexLabels` 길이, `lines` 끝점 형식, `net`이 정해진다.

| `shape` | 도형 | `size` | 꼭짓점 수 (`vertexLabels` 길이) | `lines` 끝점 | `net` |
|---|---|---|---|---|---|
| `cuboid` | 직육면체 | `{ width, depth, height }` | 8 | 다면체형 | `{ layout: "cross" }` |
| `cube` | 정육면체 | `{ edge }` | 8 | 다면체형 | `{ layout: "cross" }` |
| `regular-tetrahedron` | 정사면체 | `{ edge }` | 4 | 다면체형 | `{ layout: "default" }` |
| `regular-octahedron` | 정팔면체 | `{ edge }` | 6 | 다면체형 | `{ layout: "default" }` |
| `regular-dodecahedron` | 정십이면체 | `{ edge }` | 20 | 다면체형 | `{ layout: "default" }` |
| `regular-icosahedron` | 정이십면체 | `{ edge }` | 12 | 다면체형 | `{ layout: "default" }` |
| `cylinder` | 원기둥 | `{ radius, height }` | 0 (빈 배열) | 원기둥형 | `{ layout: "default", seam? }` |
| `cone` | 원뿔 | `{ radius, height }` | 1 (꼭짓점) | 원뿔형 | `{ layout: "default", seam? }` |

- `size`의 값은 모두 0보다 크고, 단위는 학습지 그대로(cm 등)다. `width` = 가로(x), `depth` = 깊이(z), `height` = 높이(y), `edge` = 한 모서리 길이, `radius` = 밑면 반지름
- `vertexLabels`: 꼭짓점마다 라벨(예: "ㄱ"), 없으면 `null`. 인덱스는 아래 꼭짓점 규칙을 따른다
- `lines`: `{ from, to }` 목록. 다면체는 두 끝점이 같은 면 위, 곡면 도형은 옆면(곡면) 위의 선만 다룬다 (밑면 원 위의 선은 지원하지 않음)
- `net.layout`: `cross`는 아래 십자형, `default`는 도형별 기본 전개도(다면체는 `frontend/src/viewer/polyhedra.ts`의 면 트리, 곡면 도형은 아래 곡면 전개도 규칙)
- `net.seam`: 곡면 도형만. 옆면을 자르는 선(모선)의 각도, 생략하면 0

### 꼭짓점 인덱스 규칙

도형 중심이 원점, 앞쪽(+z) = 보는 사람 쪽. 고리 모양으로 놓인 꼭짓점은 **위에서 내려다볼 때 앞에서 시작해 반시계 방향**(앞 → 오른쪽 → 뒤 → 왼쪽)으로 번호를 붙인다.

**직육면체·정육면체 (8)**

```
      7 ------- 6        아랫면: 0 앞왼쪽, 1 앞오른쪽, 2 뒤오른쪽, 3 뒤왼쪽
     /|        /|        윗면:   4~7 은 각각 0~3 바로 위
    4 ------- 5 |
    | 3 ------|- 2
    |/        |/
    0 ------- 1
```

면으로 보면(바깥에서 볼 때 반시계): 앞면 0-1-5-4, 뒷면 3-7-6-2, 윗면 4-5-6-7, 아랫면 0-3-2-1, 왼쪽 0-4-7-3, 오른쪽 1-2-6-5.

**정사면체 (4)**: 밑면 정삼각형 0 앞왼쪽, 1 앞오른쪽, 2 뒤, 그리고 3 꼭대기.

**정팔면체 (6)**: 0 꼭대기, 1~4 가운데 정사각형(1 앞, 2 오른쪽, 3 뒤, 4 왼쪽), 5 바닥.

**정이십면체 (12)**: 0 꼭대기, 1~5 위 고리(1이 앞), 6~10 아래 고리(위 고리에서 36° 더 돈 위치부터, 6은 1과 2 사이 아래), 11 바닥.

**정십이면체 (20)**: 윗면이 수평인 자세. 0~4 윗면 정오각형(0이 앞), 5~9 위 고리(각각 0~4와 같은 방향, 바로 아래), 10~14 아래 고리(36° 더 돈 위치부터, 10은 5와 6 사이), 15~19 아랫면 정오각형(각각 10~14와 같은 방향, 바로 아래).

**원뿔 (1)**: 0 꼭짓점(apex). **원기둥**: 꼭짓점 없음.

정다면체 4종의 면 목록(어느 꼭짓점끼리 한 면인지)은 `frontend/src/viewer/polyhedra.ts`의 데이터가 기준이다.

### 선분 끝점

**다면체형** (직육면체, 정육면체, 정다면체): 둘 중 하나

- `{ "vertex": 5 }`: 꼭짓점 5
- `{ "edge": [4, 5], "t": 0.5 }`: 모서리 4→5 위의 점. `t`는 `edge[0]`에서 `edge[1]` 쪽으로 간 비율(0~1). 0.5면 중점

**곡면 도형의 각도**: 위에서 내려다볼 때 앞(+z)을 0°로 반시계 방향으로 잰 각도(도)다. 값은 `seam`부터 `seam + 360` 사이로 쓴다. `seam`과 `seam + 360`은 입체에서는 같은 위치지만, 전개도에서는 왼쪽 끝과 오른쪽 끝으로 다르다 (실을 한 바퀴 감는 문제에 필요)

**원기둥형**: 셋 중 하나

- `{ "top": 90 }`: 윗면 둘레 위, 각도 90°
- `{ "bottom": 0 }`: 밑면 둘레 위, 각도 0°
- `{ "surface": { "angle": 180, "h": 0.5 } }`: 옆면 위. `h`는 밑면 0 ~ 윗면 1

**원뿔형**: 셋 중 하나

- `{ "apex": true }`: 꼭짓점
- `{ "base": 0 }`: 밑면 둘레 위, 각도 0°
- `{ "surface": { "angle": 180, "r": 0.5 } }`: 옆면 위. `r`은 모선을 따라 꼭짓점 0 ~ 밑면 둘레 1

**곡면 위 선은 "전개도 위의 직선"으로 정의한다.** 두 끝점을 곡면 전개도에 놓고 직선으로 이은 것이 그 선이다. 그래서 "실을 감았을 때 최단 거리"와 같다.

### 전개도 `cross` (직육면체·정육면체)

```
        [윗면]
[왼쪽] [앞면] [오른쪽] [뒷면]
        [아랫면]
```

### 곡면 전개도 (원기둥·원뿔 `default`)

- **원기둥**: 옆면은 가로 `2π × radius`, 세로 `height`인 직사각형이다. 각도 `seam`에서 잘라서 왼쪽 끝 = `seam`, 오른쪽 끝 = `seam + 360`이 된다. 전개도 좌표 `(angle, h)` → 직사각형 위 `(가로 = (angle − seam) / 360 × 2π × radius, 세로 = h × height)`. 윗면·밑면 원은 직사각형 위·아래 변의 가운데(`seam + 180`)에 붙는다
- **원뿔**: 모선 길이 `L = √(radius² + height²)`. 옆면은 반지름 `L`, 중심각 `360° × radius / L`인 부채꼴이다. 각도 `seam`에서 자른다. 전개도 좌표 `(angle, r)` → 부채꼴 위 극좌표 `(꼭짓점에서 거리 = r × L, 회전각 = (angle − seam) × radius / L)`. 밑면 원은 부채꼴 호의 가운데(`seam + 180`)에 붙는다

### 예시

**직육면체**: 4×2×3에 앞면 대각선 하나와 윗면 가운데를 가로지르는 선 하나가 있는 경우
([frontend/src/shared/mock.ts](../frontend/src/shared/mock.ts)와 같은 내용이며, 지금 `/analyze`가 이 값을 돌려준다):

```json
{
  "shape": "cuboid",
  "size": { "width": 4, "depth": 2, "height": 3 },
  "vertexLabels": ["ㄱ", "ㄴ", "ㄷ", "ㄹ", "ㅁ", "ㅂ", "ㅅ", "ㅇ"],
  "lines": [
    { "from": { "vertex": 0 }, "to": { "vertex": 5 } },
    { "from": { "edge": [4, 5], "t": 0.5 }, "to": { "edge": [6, 7], "t": 0.5 } }
  ],
  "net": { "layout": "cross" }
}
```

**원기둥**: 반지름 3, 높이 10. 밑면 앞쪽 점에서 실을 옆면에 한 바퀴 감아 바로 위 윗면 점까지 가는 최단 거리 (전개도에서는 직사각형의 대각선):

```json
{
  "shape": "cylinder",
  "size": { "radius": 3, "height": 10 },
  "vertexLabels": [],
  "lines": [{ "from": { "bottom": 0 }, "to": { "top": 360 } }],
  "net": { "layout": "default", "seam": 0 }
}
```
