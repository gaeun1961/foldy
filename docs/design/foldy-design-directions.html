Foldy의 정체성은 “사진 한 장이 손으로 만지는 3D 교구가 되는 순간”입니다. 세 안은 같은 기능과 같은 3개 화면을 서로 다른 감성으로 표현해, 팀원이 옆에서 바로 비교하고 선택할 수 있게 만들었습니다.

범위 안내이 문서는 디자인 탐색용이며 현재 서비스 코드·UI 스펙·TODO-15 발표 자료를 변경하지 않습니다. 최종안 선택 뒤 docs/specs/ui.md와 실제 토큰을 함께 갱신하는 것이 다음 단계입니다.
00 / QUICK PICK

먼저, 셋 중 어떤 인상인가요?

기능 차이가 아니라 “학생에게 어떤 첫인상을 줄지”를 고르는 단계입니다. 각 카드의 한 문장만 읽어도 회의가 시작되도록 구성했습니다.

A · 현재 자산을 가장 잘 살림

종이 공작실

책상 위 펼친 책과 색연필, 손으로 눌러 보는 클레이 버튼. 따뜻하고 친근한 교구처럼.

추천: 데모 안정성 · 브랜드 연속성
B · 학습 효율이 가장 선명함

호기심 실험실

3D 도형이 주인공인 넓은 캔버스와 단정한 실험 패널. 관찰하고 발견하는 과학 도구처럼.

추천: 장시간 사용 · 수업 현장
C · 발표에서 가장 눈에 띔

비주얼 클래스

큰 문장, 강한 대비, 한 화면 한 메시지. 어려운 개념을 짧고 기억나게 설명하는 에디토리얼 화면.

추천: 메이커톤 발표 · 스토리텔링

현재 Foldy에서 이미 꺼내 쓸 수 있는 토큰

문서의 희망값이 아니라 실제 frontend/src/index.css에서 추출한 기준값입니다. A안은 이 토큰을 정리해서 쓰고, B·C안은 구조를 유지한 채 팔레트와 위계만 바꿉니다.

가져온 것

페이퍼로지의 메시지 중심 슬라이드 구성, 강한 크기 대비, 화면을 좌우 두 덩어리로 나누는 정보 위계.

바꿀 것

설정은 보조로 밀고 “질문 → 행동 → 발견” 문장을 화면마다 하나만 크게 보여 줍니다.

주의점

발표에서는 강하지만 반복 학습 화면 전체에 쓰면 피로할 수 있어 시작·설명·완료 화면에 집중 적용합니다.

RECOMMENDATION

A를 기반으로 B의 학습 흐름, C의 설명 화면을 섞는 안을 추천합니다.

현재 구현 자산과 가장 가까운 A로 일정 리스크를 줄이고, B의 “먼저 예상하기”와 C의 “한 화면 한 메시지”만 선택적으로 가져오면 팀원이 다시 만드는 양을 최소화하면서도 발표 화면이 또렷해집니다.
