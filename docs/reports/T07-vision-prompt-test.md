## 요약
- 학습지 사진 13장(직육면체·정육면체)과 사진별 정답을 준비하고, 비전 프롬프트와 정확도 측정 도구를 만들었다
- 사진 13장 중 7장이 기존 계약(십자형 하나)으로 안 옮겨져서 계약을 넓혔다 (전개도 grid, 이슈 #67, `T00-grid-net.md`). 프롬프트도 grid 를 뽑게 했다
- Gemini(`gemini-3.5-flash`) 첫 측정에서 답이 온 7장은 잘못 그린 전개도 1장을 빼고 모든 항목이 맞았다. 나머지 6장은 모델 과부하(503)였고, 다시 재려다 무료 한도(모델당 하루 20번, 429)에 걸렸다

## 변경 범위
- `backend/app/ai/vision_prompt.py`: 비전 프롬프트. 인쇄된 것만 읽기(학생 손글씨·연필 무시), 돌아간 사진은 글자가 바로 서게, 여러 개면 ①번. 전개도가 있으면 grid(면 직사각형·면 글자·색칠·전개도 라벨·전개도 위 선), 겨냥도만 있으면 cross(꼭짓점 0~7 규칙)
- `backend/app/ai/vision.py`: `recognize()` (사진 + 프롬프트 → Gemini → `ShapeScene` 검증). 키 없음·호출 실패·시간 초과·검증 실패는 모두 `VisionError`. `/analyze` 연결은 TODO-8
- `backend/evals/`(새 폴더): `vision_eval.py`(측정, 503·시간 초과는 10·30초 쉬고 다시), `answers.json`(사진 13장 정답, 사진에서 알 수 없는 항목은 `skip`). `photos/`, `results/`는 git 에 안 올린다
- `backend/tests/test_vision_eval.py`: 비교 함수 검사 (LLM 호출 없음)
- `requirements.txt`에 `httpx`(시간 초과 예외를 잡으려고 직접 씀), AGENTS·README 검증 명령에 `test_vision_eval`

## 채점 방법
- 항목: 도형, 치수, 전개도(cross/grid 와 grid 면 배치), 라벨, 면 표시(grid 면 글자·색칠), 선
- 치수는 세 값을 정렬해서 1% 까지 (전개도만 보면 어느 면이 앞인지 정할 수 없음)
- grid 는 전개도를 평행이동·크기와 상관없이 맞춘 뒤(왼쪽 위 0, 긴 쪽 1) 6% 까지 같다고 본다. 사진 원근·어림 때문
- 정답 13장 중 바른 전개도는 접으면 닫히고 잘못 그린 전개도(193744)는 안 닫히는 것을 뷰어(`netCheck`)로 확인했다

## 결정
- 정답을 바로 쓸 수 없는 문제(전개도 여러 개 고르기)는 도형만 채점, 겨냥도 입체 선 + 전개도가 같이 있는 문제(193756)는 grid 로 적고 선은 채점에서 뺐다
- 사진은 저작권 때문에 저장소에 올리지 않는다. 이 작업 중 사진이 grid PR(#68)에 같이 커밋돼 main 에 올라간 사고가 있었고, main 기록을 다시 써서 지웠다 (닫힌 PR 캐시는 GitHub 지원 요청 필요)
- 사진 인식이 막힐 때(한도·인터넷)를 대비해, 기본 길은 LLM 없이 **전개도 직접 만들기**(TODO-12)로 하기로 했다. 전개도 11가지 중 고르기는 목록에 없는 모양이 있고, 전개도를 머릿속으로 못 접는 학생에게 오히려 어려워서 하지 않는다
