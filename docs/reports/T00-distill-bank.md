# 기록 증류와 엄격한 정답 은행

- 일시: 2026-11-01
- 이슈: #161

## 구현

- `evals/distill.py`: 학생 선택과 추천의 IoU 0.5 일대일 매칭, 세션 마지막 피드백, 오류·시간 집계. 사진이나 자유 텍스트를 출력에 넣지 않는다.
- `npm run test:cases -- --manifest 외부경로 [--tune]`: 실제 추천 알고리즘 재실행, 개발 자료에서 격자 맞춤, 원본 해시가 분리된 평가 자료에서 확인. 상수는 자동 변경하지 않는다.
- 기록 모드 정답 은행: 도형·문제 dHash 거리 0 및 SHA256 완전 일치. [맞음] 저장, [틀림] 제거, 저장된 답 표시. 사진 자체는 저장하지 않으며 최대 50개다.

## 검증

- frontend build/lint/test, backend ruff check/format과 기존 필수 검사, 새 distill 검사 통과.
- 실제 개발 서버 + Chromium 390px: 합성 사진의 맞음 저장 → 동일 입력 API 생략 → 저장된 답 표시 → 틀림 제거 → API 재호출 통과. 페이지 오류 0. 실제 인식 정확도 검사는 아니다.
- 로컬 기존 기록: 세션 2개, 읽기 4건, 읽기 오류 2건, 마지막 맞음 1개·미판정 1개. 추천/학생 네모 매칭 4개는 정답 정확도가 아닌 선택 대리 지표다.
- 외부 연구 자료의 에이전트 주석으로 개발 4개·평가 12개, 기본 포함 28개 TUNE 후보 검사. 제안값 ink 0.6, open 3, 나머지 기존값. 개발 매칭 1·추가 0·놓침 3(F1 0.4), 평가 매칭 1·추가 3·놓침 11(F1 0.125).
- 낮은 평가 결과와 사람 미검수 상태 때문에 서비스 TUNE은 바꾸지 않았다. 이를 추천/인식 개선 성공으로 보고하지 않는다. 평가 자료는 이번 선택에 사용하지 않았다.

## 한계와 병합 순서

정답 은행은 기록 모드의 동일 이미지 재사용이다. 다른 촬영·압축·숫자 변경에 대한 근사 검색은 하지 않는다. 정답 심사 #162와 사람 승인 없이 공용 은행을 자동 배포하지 않는다. #180 → #181 이후 이 PR을 main으로 변경한다. Android 앱 실측은 기존 자동 승인 정책 거절로 미완료다.
