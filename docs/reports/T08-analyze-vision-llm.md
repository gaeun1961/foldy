## 요약
- `/analyze`가 목 데이터 대신 Gemini 사진 인식 결과(`vision.recognize`, TODO-7 프롬프트)를 돌려준다
- 실패하면 목 데이터를 돌려주지 않고 에러를 돌려준다: 사진에서 도형을 못 읽으면 422 "사진에서 도형을 찾지 못했어요", 키 없음·하루 한도 초과·과부하·시간 초과면 503 "지금은 사진 인식을 쓸 수 없어요". 원인은 서버 로그에만 남긴다
- 같은 사진은 다시 부르지 않는다(사진 해시로 최근 100장 기억). 모델 과부하(503)는 2초 쉬고 한 번 더 부른다
- 사진을 올렸을 때 목 도형(선 2개)이 나오던 문제가 없어졌다

## 결정
- 실패 시 목 도형을 돌려주지 않는다. 학생이 틀린 도형을 사진 결과로 오해하지 않게, 실패는 안내 문구로 보여주고 수동 입력(전개도 직접 만들기, TODO-12)으로 넘긴다
- 무료 한도(모델당 하루 20번)를 아끼려고 같은 사진 결과를 기억한다. 서버를 다시 켜면 사라진다(메모리). 실패는 기억하지 않아서 한도가 풀리면 다시 시도된다
- 한도 초과(429)·시간 초과는 다시 불러도 소용없어서 바로 503, 과부하(503)만 한 번 더
