## 요약
- 3D 바닥을 **책상 위에 펼친 책**으로 바꿨다. 전개도가 오른쪽 페이지 위에 놓이고, 접으면 페이지에서 일어선다. 왼쪽 페이지에는 "직육면체의 전개도 / 가로 4 · 세로 2 · 높이 3 / 할 일 한 줄"을 명조체로 찍는다
- 넓은 화면은 책 장면이 화면 전체를 채우고, 그 위에 반투명 종이색 패널 두 개를 띄운다: 왼쪽 위 "foldy · 도형 만들기" 카드(접을 수 있음), 아래 가운데 바(안내 문구 + 접기 + 선 긋기 + 보기). 좁은 화면은 위 3D(50%, 고정) → 아래 바 → 만들기 카드
- 분위기 레퍼런스: [Every Joule](https://iamtechartist.com/every-joule/) (책 위에서 그림이 3D로 일어남, 장면 위 반투명 바 하나)

## 결정
- **가벼운 책 장면** (사용자 결정): 레퍼런스의 표지 화면, 페이지 넘김, 카메라 이동, 나무·펠트 질감 이미지는 하지 않았다. 이미지 파일 없이 상자·평면과 캔버스 텍스처(종이 그늘·글자, 옅은 나뭇결)만 쓴다
- 바닥(y = 0)을 그대로 오른쪽 페이지로 써서 면 트리·접기·클릭 코드는 바꾸지 않았다. 페이지 크기는 다 펼친 전개도 범위 + 여백 15%(세로는 가로의 1.3배 이상)
- 왼쪽 페이지 글은 UI 문구라 `ViewerProps.pageText`로 받는다 (viewer.md 먼저 고침). 바뀌면 다시 만든다
- 페이지 윗면은 도형 크기의 1% 아래. 처음 0.3%로 했더니 먼 쪽 면에서 페이지와 깊이가 겹쳐 줄무늬가 졌다
- 그림자는 도형 둘레만 덮는다. 책 전체로 넓혀 봤지만 같은 그림자 지도로 넓은 곳을 덮어 도형 그림자가 흐릿해져서 되돌렸다. (반쯤 접은 상자 안쪽의 밝은 조각은 열린 윗면으로 들어온 빛이라 정상)
- 가로로 긴 화면에서는 아래 바가 3D 위에 떠 있어서, 카메라가 보는 점을 도형 크기의 45%만큼 앞으로 옮겨 도형을 화면 위쪽에 둔다
- 만들기 카드와 보기 메뉴는 `<details>`로 접고 펼친다 (JS 상태 없음)
- 명조체는 시스템 글꼴(AppleMyungjo, 나눔명조, Noto Serif KR 순)만 쓴다. 발표장 인터넷이 없어도 되게 웹폰트를 받지 않는다. 없으면 기본 serif
- 도형이 없을 때 안내는 "학습지 사진을 올리거나 직접 만들어 보세요"로 바꿨다 (좁은 화면에서는 카드가 아래라 "왼쪽"이 틀림)

## 확인
- `npm run build`, `npm run lint`, `npm test` 통과
- 헤드리스 크롬(SwiftShader)으로 "이 치수로 만들기" → 펼침 0%·접기 60%를 1440×900, 1280×800, 1024×768(노트북), 820×1180(태블릿), 390×844(휴대폰)에서 찍었다. 모든 크기에서 가로 스크롤 없음(`scrollWidth` = 화면 폭), 도형이 아래 바에 가리지 않음
- 도형 없는 시작 화면, 만들기 카드 접기, 보기 메뉴 펼침을 찍어 확인

## 리스크/이슈
- 넓은 화면에서 만들기 카드가 왼쪽 페이지 글 일부를 가린다. 카드 제목 줄을 눌러 접으면 보인다
- 도형이 없을 때는 책 없이 책상 색 바탕만 보인다. 빈 책(또는 표지)을 보여주면 더 자연스럽다
- 좁은 화면의 3D 높이(50%)에서는 도형이 작게 보인다
- 실제 그래픽 카드·프로젝터에서는 아직 보지 않았다 (헤드리스는 SwiftShader)
