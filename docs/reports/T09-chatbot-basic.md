## 요약

## 결정
- **LLM은 Gemini** (사용자 결정): Google AI Studio에서 키를 바로 받을 수 있어서. 키 이름은 프로젝트 규칙대로 `LLM_API_KEY`이고, SDK 기본 이름(`GEMINI_API_KEY`) 대신 코드에서 직접 넘긴다
- **모델은 `gemini-3.5-flash-lite`**: 2026-10-27 확인 시 `gemini-flash-latest`·`gemini-3.8-flash`는 Google 쪽 과부하로 504(시간 초과)·503이 났고, `gemini-2.5-flash`는 "새 사용자에게는 더 이상 제공하지 않음"(404)이었다. flash-lite는 1~2초에 답했고 짧은 힌트에는 충분했다
- CLI(Gemini CLI)로 부르는 방식도 이야기했지만, 키를 받아서 만들지 않았다
- 시스템 프롬프트: 초5~중1 눈높이, 정답·계산 결과를 말하지 않고 힌트 하나 + 생각할 질문, 화면 조작(접기 슬라이더, 돌려 보기, 꼭짓점·모서리 누르기) 권하기, 존댓말만, 꼭짓점은 라벨로 부르고 내부 번호·JSON 낱말은 말하지 않기, 마크다운 기호 쓰지 않기. ShapeScene 읽는 법(직육면체 꼭짓점·면 번호)을 프롬프트에 넣었다
- 첫 시도에서 반말("반가워", "~볼까?")이 섞이고 "ㄱ(0번)", "꼭짓점 0과 꼭짓점 5"처럼 내부 번호를 말해서, 이 두 가지를 프롬프트에 금지로 적었다
- `genai.Client(...)`를 변수에 담지 않고 바로 `.models.generate_content`를 부르면 요청 전에 클라이언트가 닫혀서 `RuntimeError: client has been closed`가 났다. 변수에 담아 해결

## 질문 예시와 답변 (목 데이터: 직육면체 4×2×3, 꼭짓점 ㄱ~ㅇ)

1. **"전개도를 접으면 ㄱ이랑 만나는 꼭짓점이 어디야?"** (1.4초)
   > 화면 아래에 있는 접기 슬라이더를 천천히 움직여서 전개도를 조금씩 접어 볼까요? 꼭짓점 ㄱ을 누르면 전개도에서 같은 곳을 가리키는 점들이 색칠되니까, 그것도 같이 눌러 보세요. 접었을 때 꼭짓점 ㄱ이 다른 어느 꼭짓점과 딱 맞닿는지 눈으로 보면 금방 찾을 수 있을 거예요.
2. **"이 직육면체 겉넓이가 얼마야? 그냥 답만 알려줘"** (1.7초)
   > 답을 바로 알려주기보다는 직접 구해 보는 게 훨씬 기억에 오래 남을 거예요. 화면의 직육면체를 돌려보며 앞면, 아랫면, 옆면처럼 마주 보는 면이 몇 개씩 있는지 찾아볼까요? 가로가 4, 세로가 2, 높이가 3이니까 면 세 개의 넓이를 각각 구해서 더하면 어떻게 될까요?
3. **"선분 ㄱㅂ은 어느 면 위에 있어?"** (1.1초)
   > 화면에 있는 접기 슬라이더를 조금 움직여서 전개도를 살짝 접어 볼까요? 꼭짓점 ㄱ과 ㅂ이 어떻게 만나고 있는지 살펴보면 어떤 면 위에 있는 선분인지 쉽게 알 수 있을 거예요. 선분 ㄱㅂ이 지나가는 네모난 면의 이름을 찾아볼까요?
4. **"오늘 점심 뭐 먹을까?"** (2.2초, 주제 밖 질문)
   > 점심 메뉴도 중요하지만, 우리 앞에 있는 직육면체 모양의 맛있는 상자부터 완성해 볼까요? 화면의 접기 슬라이더를 살짝 움직여서 입체로 만들어 보면 점심 생각도 싹 달아날 만큼 신기한 모양이 될 거예요. 앞왼쪽아래 꼭짓점 ㄱ에서 앞오른쪽위 꼭짓점 ㅂ까지 이어진 선을 보면 어떤 면을 가로지르게 되는지 찾아볼 수 있을까요?

## 리스크/이슈
- 2번 답의 "면 세 개의 넓이를 더하면"은 겉넓이의 절반이다. 앞 문장에서 마주 보는 면 개수를 먼저 묻기는 하지만, 힌트가 틀린 방향으로 읽힐 수 있다. 수학적으로 틀린 힌트가 나오는지 더 많은 질문으로 확인해야 한다
- 답이 "꼭짓점 ㄱ을 누르면"처럼 라벨로 말하지만, 3D 화면에서는 한글 라벨을 그리지 않는다(TODO-5 결정). 학생은 학습지에서 라벨을 보고 화면의 점을 찾아야 한다
- 대화 기록을 보내지 않아서 한 질문씩 따로 답한다 (API가 `message` 하나만 받는다)
- 모델 가용성은 계속 바뀐다. 504·503이 나면 `chat.py`의 `MODEL`만 바꾸면 된다
