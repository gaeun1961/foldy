# 사진 인식에서 검증 가능한 개선으로

- 일시: 2026-11-01
- 이슈: #164
- 발표용 2장: [HTML](recognition-process.html). 브라우저 인쇄는 가로 16:9 두 장, 화면에서는 반응형으로 읽는다.
- UI 기준: `frontend/src/index.css`의 잉크·종이·책상·그림자와 `docs/specs/ui.md`의 색연필 4색. 팀원 시안 원본은 수정하지 않는다.

## 발표 문장

“사진을 읽는 것에서 끝내지 않고, 학생이 추천 네모를 어떻게 고쳤는지와 결과가 맞는지를 기록합니다. 그 기록으로 실패를 모으고, 독립 심사와 사람 확인을 거쳐 규칙과 검증 자료를 개선합니다. 학생이 확인한 같은 문제는 저장된 답으로 다시 열 수 있게 개발 중입니다.”

여기서 증류는 모델 가중치 학습 완료를 뜻하지 않는다. 실패 유형·퓨샷·규칙 정리와 평가 반복이다. 사진·기록은 로컬에 두며 git에 올리지 않는다. 기록 모드는 개발/실측 빌드에만 켠다.

## 숫자와 한계

| 항목 | 확인한 근거 | 발표 시 제한 |
|---|---|---|
| 도형 두 개 + 문제 글, 개선 전 4회 | 22.3 / 61.8 / 19.0 / 56.5초 | 한 사진 반복, 일반 서비스 통계 아님 |
| 같은 측정의 개선 후 4회 | 21.8 / 14.0 / 36.7 / 15.7초 | 14~22초 사례가 있으나 36.7초도 포함 |
| 후속 도형 두 개 3회 | 17.7 / 17.8 / 17.0초 | 데스크톱·예열된 agy 조건 |
| 추천 네모 | 학습지 2장 0.02~0.08초 | LLM 인식 전체 시간이 아님 |

근거: [agy 속도](T00-agy-speed.md), [추천 네모](T00-suggest-box.md). 이슈의 “50초 → 14~22초”는 요약 문구일 뿐 일정한 성능 보장이 아니다. 새 Flash-Lite 연구는 엔진·입력·평가 방식이 달라 같은 막대에 섞지 않았다.

## 디자인과 사진 프레임

순서도는 번호·화살표·문장으로 순서를 표시하고 색만으로 뜻을 전달하지 않는다. 종이 카드 안에 둥근 사진 프레임을 재사용한다. 저작권 사진 대신 삽입할 화면 위치를 표시했다. 발표자가 승인된 실측 화면을 넣을 때도 같은 프레임을 유지하면 된다.
